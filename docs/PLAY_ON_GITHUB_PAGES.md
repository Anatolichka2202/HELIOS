# HELIOS Venus — как запустить браузерную игру

**Дата:** 2026-10-23.

## Главный адрес после успешной публикации

https://anatolichka2202.github.io/HELIOS/

Он автоматически перенаправляет на `/HELIOS/lite/index.html`.

**Пока GitHub Pages не настроен и успешно опубликован, URL может возвращать 404.** Это не значит, что исходники игры отсутствуют. В корне репозитория есть `index.html` и `.nojekyll` для упрощения публикации из ветки.

## Самый простой и устойчивый путь — публикация из ветки

1. Зайти в [HELIOS — Settings → Pages](https://github.com/Anatolichka2202/HELIOS/settings/pages).
2. Найти **Build and deployment → Source**.
3. Выбрать **Deploy from a branch**.
4. **Branch:** `main`; **Folder:** `/(root)`.
5. Нажать **Save**.
6. Открыть [Actions](https://github.com/Anatolichka2202/HELIOS/actions) и дождаться **успешного** GitHub Pages deployment. В Settings → Pages после публикации появится ссылка **Visit site**.
7. Открыть сайт и проверить версию **PLAYABLE V0.7**. Если появилась ошибка 404, посмотреть Actions логи — возможно Pages ещё не собран или не разрешён политикой репозитория.

Если пользователь уже выбрал **Source: GitHub Actions**, альтернативно можно оставить этот вариант и запустить workflow `Publish HELIOS Venus Lite`. Он тестирует JavaScript, затем упаковывает `lite/` в корень артефакта и разворачивает через `actions/deploy-pages`. **Не нужно выбирать оба способа одновременно.**

Публикация `main/(root)` проще для первичного ознакомления, поскольку не зависит от тестового шага игрового workflow. **CI-проверки при этом следует продолжать запускать отдельно**.

## Проверка, что открылась именно игра

- На заголовке видно `PLAYABLE V0.7`.
- Есть «Кампания», «Свободная сессия», показатели бюджета/науки/энергии.
- Есть венерианская иллюстрация, зоны и проекты.
- Сначала провести научный совет, выбрать финансирование, построить архив и зонд.
- После зонда и ретранслятора должен появиться выбор конструкции аэростата.
- Сохранение должно работать, а при повторном открытии состояние должно восстановиться.

## Если 404 не исчезает

1. Проверить, что открыт URL с точным путём `/HELIOS/`.
2. В Pages должен отображаться активный источник `main /(root)` либо успешное развёртывание workflow.
3. Просмотреть **Actions → pages build and deployment** (при branch deployment) или **Publish HELIOS Venus Lite** (при workflow).
4. Убедиться, что выбранный build/deploy завершился зелёным результатом.
5. Сайт может начать работать не одновременно с нажатием Save; требуется фактическое завершение публикации. Если открыть сохранённую домашнюю ссылку не получается, нажать **Visit site** в Settings → Pages.

Важно: опубликование GitHub Pages не подтверждено одной лишь записью файла в Git. Не давать пользователям ссылку как гарантированно рабочую, пока её не открыл реальный клиент.

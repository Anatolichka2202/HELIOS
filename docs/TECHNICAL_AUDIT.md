# Технический аудит HELIOS — 22.10.2026

## Executive state

Исходники разделены на активный web-прототип, два нативных визуальных scaffolds, отдельный C++ research core, общий JSON-контракт, архив и сценарные документы. Это **набор прототипов**, а не три интегрированные игры. Единственная подсистема, у которой в наличии игровой цикл и независимые unit-тесты, — Lite.

## Проверено

- Исторический Python P1: `python -m unittest discover -s tests -v` — **5/5 прошли локально** на архивной копии.
- Исходный C++ код из архива 0.2: CMake + CTest — **1/1 прошёл локально**.
- Исторический Lite 0.2: JavaScript syntax check — успешен локально.
- Актуальная модель Lite и контракты: 20 тестов исполнены в контролируемой JavaScript-среде без Node/браузера; **20/20 прошли**. Это не эквивалент подтверждённого результата GitHub Actions.
- UE5/Unity editor, упаковка Android/iOS, настоящая доступность GitHub Pages и тест iPhone — **не подтверждены**.

## Реальные проблемы и риски

### P0. Веб-демонстрация не подтверждена как опубликованная
В репозитории имеется GitHub Pages workflow. Если Pages не включена или workflow упал, ссылка на игру не заработает. Требуются настройка источника, проверка CI, HTTPS URL и тест Safari. Не выдавать страницу исходников за играемую версию.

### P0. Дублирование игровых моделей
`lite/engine.js` содержит текущую экономику Венеры; `core/` — **другую**, несовместимую по правилам C++-модель; Python P1 — ещё более раннюю. `shared/venus-scenario.json` пока не читается нативными клиентами. Нельзя подключать все три как «общее ядро» без явной миграции моделей и контрактных тестов.

### P0. Реалистичность модели
Годовой шаг, условные ресурсы, вымышленные бюджеты, ровно два года доставки, искусственный уровень штормов. Это правильная демонстрационная экономика, но не рассчитанная баллистика, производство или климат. В документации явно отделены игровая абстракция и физика.

### P1. Архитектура игры
`engine.js` поддерживает чистые переходы состояния; UI зависит от DOM и не может использоваться непосредственно в Unity/UE. В следующих итерациях разделить сценарные тексты/диалоги, конфигурацию проектов, локализации, системы логистики, истории и экономических прогнозов по файлам. Не допускать повторной реализации одинаковых правил в трёх клиентах.

### P1. Сохранения
Локальное сохранение на устройстве, без облачного аккаунта и переноса между платформами. Старые v4 сохранения совместимы после расширения необязательных полей, но массовые миграции пока не реализованы. Нужны тесты повреждённых/частично заполненных данных, версия контракта, импорт/экспорт файла и локальные резервные копии.

### P1. QA
22 теста игровой логики и контрактов, 6 DOM smoke-тестов через Node test harness проверяют только модели и структуру. Нет реального touch end-to-end тестирования, профилирования, проверок на iOS Safari, а также сборок UE/Unity. GitHub CI остаётся первичным gate, не заменяет реальные устройства.

### P1. Gameplay
Финансирование стало ветвящимся политико-экономическим решением; появился риск аварийного завершения экспедиции и необходимость перевозок. Но экономические параметры подбираются вручную. Нет отдельных производственных цепочек, политических коалиций, локаций облачных станций, населения, труда и реалистичной надежности.

### P1. Визуальные материалы и лицензирование
Новый SVG аэростата создан как собственный исходник и лежит в `lite/assets/`. Концепт из ImageGen показан в переписке, но full-resolution PNG **пока не импортирован на GitHub** из-за ограниченного канала загрузки бинарных данных. Внешние AsyncImage/поисковые референсы не относятся к нашим ассетам и не должны копироваться в репозиторий без лицензий.

### P2. PC / Unity технический долг
UE акторы используют встроенные сферы без материалов, сцены/камеры/освещения как готового уровня нет. Unity `OnGUI` — отладочный интерфейс, не touch-first финальная UI-система. Не гарантирована компиляция в целевых редакторах.

### P2. История и версия проекта
Старый Python перенесён отдельно в архив. В Git присутствует HTML-вариант 0.1, но исходный snapshot Lite 0.2 из ZIP ещё не импортирован как полный отдельный архив. Текущий Lite уже наследует концепцию того прототипа. Для строгой полноты нужен импорт бинарного архива/неизменённых файлов.

## План последующих изменений

1. Закрыть канал поставки: Pages → HTTPS → iPhone → telemetry-free public playtest.
2. Перенести весь действительно доступный исторический исходный код, не путая его с активным.
3. Провести сценарный walkthrough: как новичок за 10 минут приходит к первому аэростату; исправить UX и баланс.
4. Добавить научно правдоподобные **масштабы**, массовый баланс, химию атмосферы и грузопотоки как отдельно документированную модель.
5. В UE/Unity: сначала компиляция и сенсорный/камерный прототип, затем интерактивный state client над единым контрактом, а не копирование lite.js.
6. Нарастить визуальное качество и права на арт отдельно от правил и сценария.

## Коммерческая граница

HELIOS PC — длительный производственный проект. Lite — средство верификации удержания и формулировки коммерческого предложения. Пока нет реальных игроков, нельзя оценивать прибыль, конверсию или CAC как факты.

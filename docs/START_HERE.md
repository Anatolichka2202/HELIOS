# HELIOS — с чего начать разработчику (без опыта в геймдеве)
**Дата:** 22.10.2026 · **срез:** Венера · **это объяснение существующего кода, не обещание готовой игры.**

## 1. Что мы вообще разрабатываем

**Одна научно-фантастическая вселенная всей Солнечной системы и три отдельных продукта:**

- **Lite:** короткая браузерная стратегия. **Именно здесь** сейчас существует работающий набор правил и сюжетных решений, который можно проверить тестами.
- **Mobile:** перспективная Unity-игра под Android/iOS с сенсорным UI и атмосферной 3D-диорамой. Пока только исходники начальной визуализации.
- **PC:** Unreal Engine 5 стратегия с 3D-станцией, кампанией и будущим ограниченным первым лицом. Пока только исходники акторов/модуля.

Первый игровой сценарий всех трёх — **Венера**. Это не означает, что франшиза ограничена Венерой.

Если хочется сначала понять идею, прочитайте **[единый индекс документов](../design/00_INDEX.md)**, затем [концепцию](../design/01_HELIOS_PRODUCT_BIBLE.md), затем [игровую экономику](../design/06_IN_GAME_ECONOMY.md).

**Самый важный факт:** `core/` сейчас не подключён к `pc/`, `mobile/` или `lite/` как production runtime. Это отдельный C++ эксперимент. Python из `archive/` — ещё более ранняя научная лаборатория. Не искать универсальный магический `SimEngine`, его ещё не сделали.

## 3. Как работает действующая Lite

```text
Игрок нажал «Построить аэростат»
       │
       ▼
lite/game.js — событие кнопки
       │  создаёт команду {type:"build", id:"aerostat"}
       ▼
lite/engine.js — apply(oldState, command)
       │  проверяет стоимость и исследования
       │  возвращает {state:newState, error:null}
       ▼
lite/game.js — записывает новый state в localStorage
       │
       ▼
render() — обновляет цифры, зоны, журнал, доступность кнопок
```

Пример: `engine.js` должен ответить, **хватает ли материалов** и **завершена ли научная миссия**. `game.js` должен только показать игроку причины и новые данные. Если правило записано в `game.js`, это вероятный дефект архитектуры.

Сейчас игра имеет командную, дискретную симуляцию:
- начало партии `create(mode)`;
- изменение состояния `apply(state, command)`;
- проверка проекта `canBuild(state, id)`;
- проверка завершённых проектов `has(state, id)`;
- чтение сохранения `restore(json)`.

Аэростат повреждается по правилам `next`, снабжение приходит не сразу, государственный/частный выбор меняет ресурсы, есть победа и поражение. Числа пока придуманы для геймплея: **не реальная физика Венеры**.

## 4. Как работать с кодом — по задачам

| Нужно изменить | Открыть | Что обязательно проверить |
|---|---|---|
| Расход снабжения, аварии, ресурсы | `lite/engine.js` | `lite/tests/engine.test.cjs` |
| Список объектов и стоимости | `shared/venus-scenario.json` + `lite/engine.js` | `lite/tests/schema.test.cjs` |
| Кнопки и подсказки | `lite/game.js` и `lite/index.html` | `lite/tests/ui.test.cjs` |
| Цвета/расположение/графика | `lite/style.css`, `lite/assets/` | `tools/verify_web_assets.py`, ручной телефон |
| Сюжетные главы | `design/` + временно `lite/game.js` | тест выбора и последствия |
| Прототип Unity | `mobile/Assets/Scripts/` | Unity Editor и реальное устройство |
| Прототип Unreal | `pc/Source/HELIOS/` | UE Editor compile и packaged Windows |
| Общая архитектура | `design/02_SHARED_GAME_CORE_SPEC.md` | согласование IDs/версии контрактов |

## 5. Минимальные команды для разработки

```bash
git clone https://github.com/Anatolichka2202/HELIOS.git
cd HELIOS

cd lite
npm run check
npm test

# запустить статический сайт (из папки lite):
python3 -m http.server 8080
# затем открыть http://localhost:8080
```

C++ исследовательское ядро:
```bash
cmake -S core -B build/helios-core -DCMAKE_BUILD_TYPE=Debug
cmake --build build/helios-core
ctest --test-dir build/helios-core --output-on-failure
```

Unreal/Unity **нужно открыть соответствующими редакторами и собрать**. Тот факт, что исходные файлы лежат на GitHub, не подтверждает, что они успешно компилируются на Windows, Android или iOS.

## 6. Как понимать текущие тесты

- Unit/contract тест проверяет логику, а не графический дизайн.
- UI smoke проверяет наличие элементов и переходы экранов в тестовой среде, **не реальный iPhone Safari**.
- CMake test проверяет отдельную C++ модель, **не Unreal**.
- CI YAML сам по себе не гарантирует зелёный статус GitHub Actions.
- Первый публичный HTTPS URL и доступность с телефона требуют отдельной проверки.

## 7. Что не нужно делать прямо сейчас

Не писать заново движок всех трёх продуктов. Не заменять систему промышленности псевдореалистичными цифрами без игрового цикла. Не добавлять аккаунты/сервер до первой работающей партии на телефоне. Не начинать MMO и 3D-открытый мир. Не объявлять статус «всё готово» из-за наличия JSON/C++ заготовок.

## 8. Что должно появиться следующим

- Размеченная единая JSON Schema + golden scenarios.
- Проверенный HTTPS игровой URL для Lite.
- Отдельный PC Unreal compile report и Unity Android build report.
- Понятная финансовая/производственная цепочка Венеры.
- Тестовый storyboard визита на аэростат от первого лица.
- Версионированный сценарный контент, вынесенный из JS.

## 9. Куда складывать новые результаты

**Код** — в `lite/`, `mobile/`, `pc/`, `core/` согласно подсистеме. **Контракты/данные** — `shared/`. **Общие правила/сюжет** — `design/`. **Исходные изображения** — `assets/` с записью в реестре; игровые оптимизированные варианты — в папках клиентов. **Тесты** — рядом с соответствующим модулем. **Старые экспериментальные версии** — `archive/`.

Если агент создаёт код, его handoff должен перечислять: файлы, проведённые тесты, статус компиляции, несовместимости и commit SHA. Без этого работа считается незавершённой.

## Продуктовая стратегия и монетизация Lite (v0.4)

Смотри [`design/11_FRANCHISE_PRODUCT_STRATEGY.md`](../design/11_FRANCHISE_PRODUCT_STRATEGY.md): это действующее решение о том, почему **Lite, Mobile и PC — три самостоятельные игры**, какой уникальный опыт они предлагают и как связаны.

Новый блок «Вселенная HELIOS» в `lite/index.html` выводится через `renderEcosystem()` в `lite/game.js` из данных `lite/ecosystem.js`. Это **не торговая платформа**, не сервер и не работающая касса. Ссылки на поддержку, доп. акты и магазины не отображаются, пока `enabled` и корректный HTTPS URL официальной страницы не заданы разработчиком. Проверка: `lite/tests/ecosystem.test.cjs`, `lite/tests/ui.test.cjs`.

В 2026 году основная метрика первых выпусков — игрок получил самостоятельное удовлетворение от Lite, а не был вынужден переходить в другой продукт. Реклама других игр не должна перекрывать аварии или важные решения.
